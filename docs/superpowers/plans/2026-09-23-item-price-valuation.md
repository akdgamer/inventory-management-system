# Item Price & Inventory Valuation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a unit purchase cost (`price`) to items, and surface per-item value and total inventory valuation in INR on the item detail page and the dashboard.

**Architecture:** A single `NUMERIC(10,2)` column on `item`, defaulted to 0 so all ~550 existing rows backfill cleanly. Alembic is bootstrapped properly (baseline stamped, then a real migration) so this and future schema changes have a path — `create_all()` cannot alter existing tables. The frontend already computes and renders these figures against a field named `price`; most frontend work is un-commenting and formatting, plus one new form input. Valuation stays client-side, as it already is.

**Tech Stack:** FastAPI, SQLAlchemy 2.0, Alembic, PostgreSQL 14, Pydantic v2, React 19, Vite, Tailwind. Deployed on Windows via scheduled tasks.

**Source spec:** `docs/superpowers/specs/2026-09-22-item-price-valuation-design.md`

### Task 4: Expose `price` through the Pydantic schemas

SQLAlchemy returns `decimal.Decimal` for `Numeric` columns, and Pydantic v2 serialises
`Decimal` to a JSON **string**. The frontend calls `item.price?.toFixed(2)`, and strings have
no `.toFixed` — so the field is typed `float` here deliberately, to emit a JSON number.
Storage stays exact decimal; only transport is float.

**Files:**
- Modify: `ims-backend/app/schemas.py:85-93` (`ItemBase`), `ims-backend/app/schemas.py` (`ItemUpdate`)

- [ ] **Step 1: Add `price` to `ItemBase`**

```python
    quantity: int
    min_threshold: int
    image_url: Optional[str] = None
    category_id: Optional[int] = None
```

to:

```python
class ItemBase(BaseModel):
    sku: str
    name: str
    description: Optional[str] = None
    quantity: int
    min_threshold: int

    image_url: Optional[str] = None
    category_id: Optional[int] = None
```

The default of `0` keeps existing API clients working without sending a price. `ge=0` rejects
a negative cost. `Field` is already imported at the top of the file.

`ItemSchema` inherits from `ItemBase`, so `price` appears in every item response with no

### Task 6: Create the currency formatting module

One module owns the currency. `Intl.NumberFormat('en-IN')` produces correct Indian
lakh/crore grouping (₹1,23,456.00), which a bare `toLocaleString()` does not. Confining the
symbol to one file is also what makes the planned currency-switching feature a change to one
module rather than a hunt across the codebase.

**Files:**
- Create: `ims-frontend/src/utils/currency.js`

- [ ] **Step 1: Write the module**

```javascript
// Single source of truth for money formatting.
// Prices are stored in INR; a future currency-switching feature changes this
// module (plus a rate lookup) rather than every call site.
const LOCALE = 'en-IN';
const CURRENCY = 'INR';

const formatter = new Intl.NumberFormat(LOCALE, {
  style: 'currency',
  currency: CURRENCY,
  minimumFractionDigits: 2,
  maximumFractionDigits: 2,
});

// Coerces anything non-numeric (undefined, null, "") to 0 so items without a
// price render as ₹0.00 rather than "NaN".
export function formatMoney(value) {
  const amount = Number(value);
  return formatter.format(Number.isFinite(amount) ? amount : 0);
}
```

Expected: `₹1,23,456.00 ₹0.00` (note the lakh grouping — 1,23,456 not 123,456)

If anything goes wrong after Task 11:

```powershell
cd C:\InventoryManagement\ims-backend
.\.venv\Scripts\python.exe -m alembic downgrade -1   # drops the price column
```

If the database itself is damaged, restore the Task 10 dump:

```powershell
& 'C:\PostgreSQL\14\bin\pg_restore.exe' -U <user> -d <db> --clean "backups\ims_db-<stamp>.dump"
```

Code changes revert with `git revert` (Task 1 is what makes this possible).

## Out of scope

Deferred to the Feature B spec: currency selection UI, live FX rate fetching, rate caching,
fallback when the rate API is unreachable, display conversion.

Not requested, deliberately not included: a price column on the Items *list* page;
cost-versus-sale-price margin tracking; historical valuation over time.

**Pre-existing bug noticed, not fixed here:** `ItemForm.jsx` reads `data.category?.id` and
`data.supplier?.id` when loading an item for edit, but `ItemSchema` returns flat
`category_id` / `supplier_id` fields and no nested objects — so editing an item silently
blanks its category and supplier. This is unrelated to pricing and should be its own fix.
